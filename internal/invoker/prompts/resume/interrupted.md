# 中断の後の再開

前の起動は、最終報告を出す前に中断した（エラー・時間切れ・停止のいずれか）。

- まず、作業ツリーとブランチの現在の状態を確かめ、済んでいることと残っていることを把握する。「続けるブランチ」の区画があれば、そのブランチが前の起動の作業の場所である。
- 状態の報告から始める。最終報告の形で、済んだこと・残り・次にすることを書く。
- 「前の報告の不備」の区画があれば、前の最終報告は出力スキーマの検査を通らなかった。その理由が区画に書かれているので、その点を直した最終報告を出す。
- 作業が残っていれば、続けて終わらせてよい。終わらせた場合は、最終報告に結果を反映する。
- 禁止する操作と最終報告の様式は、最初の依頼のまま変わらない。
- 作業を始める前に、現在のブランチと未コミットの変更の有無を git で確かめる。自分の課題のブランチでなければ、未コミットの変更が無いことを確かめてから切り替える。別の課題のブランチへ merge・rebase・reset をしない。切り替えに失敗したら、その後の git 操作をせず報告で止まる。起動時のブランチ名を報告の assumptions に書く。
