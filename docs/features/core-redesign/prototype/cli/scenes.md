# CLI の試作（`flywheel` コマンドのやりとり）

コマンドの名前とフラグは案です。「いま進められること」は、新しいコマンドを足さず、いまある `flywheel status` の出力を改めて出します（`next` は「次へ進める」と読めるため。オーナー 2026-11-17）。出力の語と並びは、Web の試作に合わせています。`C-12` などは課題の ID、`T-3` はタスクの ID、`F-21` はフォローアップの ID です。

## C1 いま進められることを一覧する

```console
$ flywheel status
Tom — いま進められること

あなたの承認を待っている（2 件）
  計画  C-14  設定の読み込みの誤りを、起動のときに知らせる
              問い 2 つ（どちらも推奨を選んである）・タスク 4 件・上限 12 USD
  完了  C-11  検証の結果に、確かめた手順を添える
              タスク 3/3 済み・課題の単位の確かめ 2/2・費用 5.8/8 USD

あなたの回答を待っている（2 件）
  C-12 › T-4  前の成果物が閉じられていたときは、どうしますか（12 分）
              1) 新しく作り直して続ける（推奨）  2) 作り直さずに、このタスクを止める
  C-13 › T-2  失敗の理由が長いときは、1 行に切り詰めますか（40 分）
              1) 切り詰めて、全文は開くと見える（推奨）  2) 全文をそのまま出す

取り込めるもの（3 件）
  #734  記録の書き出しを、期間で絞れるようにする（親。子 3 件）
  #731  表示の時刻を、利用者の地域の時刻で出す
  #733  長い題名が、一覧で切れる

サイクル: 走っている（作業中 2 件・あなた待ち 1 件・費用 14.6/40 USD）
```

進められるものが無いとき:

```console
$ flywheel status
Tom — いま進められるものはありません。
  あなたを待っているもの 0 件・取り込めるもの 0 件
  未のフォローアップ 2 件（flywheel followup list）
$ echo $?
0
```

## C2 計画を承認する

```console
$ flywheel show C-14 --plan
C-14  設定の読み込みの誤りを、起動のときに知らせる   [計画の承認を待っている]
方針: 起動のときに設定を読み、誤りがあれば場所と直し方を出して止める。
完了したら見えるもの:
  - 誤った設定で起動すると、どの行が誤りかが出る
やらないこと:
  - 設定の形そのものは変えない
問いと推奨:
  論点: 知らせ方
    Q1 誤りが複数あるとき → 1) 全部まとめて出す（推奨）  2) 最初の 1 つだけ出す
  論点: 止め方
    Q2 警告だけの誤りのとき → 1) 起動を続ける（推奨）  2) 止める
タスクのツリー（4 件・上限 12 USD・統合先を使う）:
  T-1 誤りの種類を洗う ─ T-2 知らせ方を決める ─ T-3 実装 ─ T-4 確かめ

$ flywheel approve C-14
C-14 の計画を承認しました（問い 2 つは推奨のまま）。
サイクルを始めました（T-1 を委譲）。この端末は待たずに戻ります。
  様子を見る: flywheel cycle status
```

推奨と違う答えを選ぶとき（計画を作り直す）:

```console
$ flywheel answer C-14 --question Q1 --choice 2
C-14 の Q1 に「最初の 1 つだけ出す」と答えました（推奨と違う答え）。
計画を作り直します。出来たら、もう一度承認を求めます。
```

承認したが、進められるものが無かったとき（前提の課題が終わっていない）:

```console
$ flywheel approve C-15
C-15 の計画を承認しました。
いま走れるタスクはありません（前提の C-12 が終わっていません）。サイクルは始めません。
```

## C3 フォローアップ

```console
$ flywheel followup list
未のフォローアップ（7 件）
C-12 差し戻しの後も、同じ成果物で作業を続けられるようにする [走っている]
  F-21  反映の後に、実際の差し戻しで同じ成果物が続くかを 1 回確かめる   （完了の検証が回した条件・3 日前）
  F-22  入力の名前を、ほかの入力と同じ並びにそろえる                   （T-2 の軽い指摘・3 日前）
  F-23  古い作業場所が残っていたときの文言を見直す                     （T-3 の気づき・2 日前）
C-9 検証の差分に、説明の文を添える [完了]
  F-17  長い説明のときの切り詰め方を決める                             （T-2 の軽い指摘・6 日前）
  F-18  反映の後に、実物の画面で 1 回確かめる                           （完了の検証が回した条件・6 日前）
課題に属さないもの
  F-25  計画の指示文で、完了条件の数が多すぎる例が続いた。上限の目安を書く （サイクルの振り返り・1 日前）
  F-19  通信の失敗のやり直しが、この 1 週間で 5 回あった。委譲先の待ち時間を見直す（サイクルの振り返り・4 日前）

$ flywheel followup done F-22 F-18 --note "T-3 の成果物で直っている／反映の後に確かめた"
F-22・F-18 を済みにしました。

$ flywheel followup drop F-23 F-17 --reason "その後の変更で、該当の箇所が無くなった"
F-23・F-17 を捨てました。

$ flywheel followup promote F-19
F-19 は課題に属していないので、新しい課題 C-16 にしました。
計画を作ります。出来たら、承認を求めます。

$ flywheel followup promote F-21
F-21 を、C-12 のタスク T-7 にしました（T-5 結合の確かめ の後）。
```

対話のセッションから、オーナーの指示で上げるとき（指示の記録つき）:

```console
$ flywheel followup promote F-19 --relayed --session <会話の識別> --quote "待ち時間の件は新しい課題にして"
```

## C4 課題を表示する（タスクのツリーを文字で出す）

```console
$ flywheel show C-12
C-12  差し戻しの後も、同じ成果物で作業を続けられるようにする
状態: 走っている 1・あなた待ち 1   タスク 2/6   費用 11.2/30 USD   統合先: 使う
取り込み元: Issue #681（親）と子 2 件

あなたを待っているもの（1 件）
  T-4 の問い: 前の成果物が閉じられていたときは、どうしますか
      1) 新しく作り直して続ける（推奨）  2) 作り直さずに、このタスクを止める
      答える: flywheel answer T-4 --choice 1

タスクのツリー（線は前提）
  T-1 仕様を書く [済み]
  └ T-2 設計 [済み]
     ├ T-3 実装: 入力を受ける [走っている・品質の検査]
     ├ T-4 実装: 同じ成果物で続ける [あなたの回答を待っている]
     ├ T-6 実装: 作業場所の片付け [次に走る・計画の後に足した]
     └─→ T-5 結合の確かめ [前提待ち: T-3・T-4・T-6]

フォローアップ: 未 3・済み 1   （flywheel followup list --issue C-12）
スーパーバイザー: 手 2・答えた問い 1 （flywheel log C-12 --kind sv）
```

## C5 走っているサイクルの様子を見る

```console
$ flywheel cycle status
サイクル: 走っている（11:32 に、計画の承認で始まった）
作業中 2 件（上限 3）・あなた待ち 1 件（上限には数えない）・費用 14.6/40 USD

見ているタスク
  C-12 › T-3  実装: 入力を受ける        委譲先が作業中（品質の検査）  18 分  2.1 USD
  C-13 › T-2  表示に出す                完了の検証をしている          1 分   1.4 USD
  C-12 › T-4  実装: 同じ成果物で続ける  あなたの回答を待っている      12 分  3.2 USD

スーパーバイザーの記録（このサイクル）
  14:31  あなたへ上げた          T-4 の問い（根拠が見つからなかった）
  14:02  添え書きを付けて差し戻した  T-3（品質の検査の失敗・1 回目）
  11:52  問いに答えた            T-2「入力は必須にしますか」→ 任意にする

$ flywheel cycle stop
サイクルを止めました。委譲先の作業は消えません。次のサイクルが続きから読みます。
```

走っていないとき・費用の上限で止まったとき:

```console
$ flywheel cycle status
サイクル: 走っていない（15:10 に終わった。全部のタスクが、あなた待ちか完了になったため）
  いま進められること: flywheel status

$ flywheel cycle status
サイクル: 費用の上限（40 USD）で止まった（16:02）
  作業中だったタスク 2 件は、委譲先の側に残っています。
  続けるには上限を上げて始め直します: flywheel cycle start --budget-usd 55
```

## 取り込むものを選ぶ

```console
$ flywheel ingest 734 731
#734（親。子 3 件）と #731 を取り込みました。課題 C-17・C-18。
サイクルを始めました（分類と計画）。計画が出来たら、承認を求めます。
#733 は取り込んでいません（取り込めるものに残ります）。
```
