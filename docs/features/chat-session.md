# 対話の欄の作り替え — 会話ごとに Claude Code を起動したまま続ける

## 概要

画面の対話の欄を、発言 1 回ごとに Claude Code（実行エンジン）を起動して返事を 1 回作る作りから、**会話ごとに Claude Code を起動したまま続ける作り**に変える。返事・道具の使用・途中経過を流して出し、許可の確認と選択肢の問い（AskUserQuestion）を画面のボタンで受ける。許可の正本を Claude Code の設定のファイルにし、宣言の `chat_tools` をやめる。欄で行った作業は課題に紐づけ、費用を課題の「仕様づくり」として数える。

要件の正本は検討の Issue（flywheel#1266）の「決まったこと」1〜8。この文書は、その最初の区切り（決定 1・5・6。決定 7 で「画面の作り替え」とした分）の仕様である。

## 背景・目的

- いまの flywheel では、仕様の文書づくりと課題の作成・分解をアプリの中で行えない。フローの移植の区切り 2（flywheel#1255）の仕様と分解は、ターミナルの対話のセッションで claude-harness のスキルを直接使って行い、flywheel の記録には残らなかった。
- いまの対話の欄は、発言 1 回ごとに `claude -p` を起動する（区切り S4d-1。`docs/features/core-redesign-s4d.md`）。返事 1 回の上限は既定で 30 ターン・600 秒（宣言の `chat_max_turns`・`chat_timeout_sec`）、選択肢の問い（AskUserQuestion）は使えず、途中経過も見えない。道具の範囲（宣言 `chat_tools`）は既定 `restricted` で、書き込みもサブエージェントも断られる。長い対話（仕様づくり・分解）には向かない。
- オーナーの決定（2026-11-24・2026-11-25）: 長い対話も Claude Code をそのまま使い、画面はチャットの見た目にする（ターミナルの画面にはしない）。チャットの Claude Code にはターミナルの Claude Code と同じ動きをさせる。チャットで行った作業は課題に紐づけ、費用も課題に数える。
- この区切りだけで、画面の中でいまのスキル（`/define-feature` など）を呼んで仕様を作れるようになる（決定 7）。仕様づくり・分解のやり方の作り直し（決定 3・4）は後の区切り（S2）で行う。

## ユーザーストーリー

オーナーとして、flywheel の画面の対話の欄で、ターミナルの Claude Code と同じように長い作業（`/define-feature` での仕様づくりなど）を頼み、返事と道具の動きを見ながら、許可の確認と選択肢の問いにボタンで答えたい。翌日に続きを話したい。欄で作った課題には、その会話と仕様づくりの費用が自動で残ってほしい。

## 機能要件

### 会話と Claude Code のプロセス

- [ ] 会話の最初の発言で、サーバは Claude Code を、入力も出力も `stream-json` の形（`claude -p --input-format stream-json --output-format stream-json`）で起動し、返事が終わってもプロセスを止めずに残す。2 通目からの発言は、同じプロセスへ送る。
- [ ] Claude Code は、許可の確認と選択肢の問いを呼び出し側（サーバ）へ渡す指定（`--permission-prompts host --permission-prompt-tool stdio`）で起動する。
- [ ] 会話の識別（UUID）は、いまと同じく flywheel が決めて渡す（新しい会話は `--session-id <会話の識別>`〔いまと同じ〕、続きは `--resume <会話の識別>`）。
- [ ] 続きの指定（`--resume`）で起動するのは、Claude Code の出力に会話の始まりの行が出たことを記録した会話だけにする（いまの分け方のまま）。始まりの行が出ていない会話は、続きの指定ではなく `--session-id <会話の識別>` で新しく起動する。
- [ ] 1 つのエージェント（ワークスペース）で、開いている会話は高々 1 つで、動いている Claude Code のプロセスも高々 1 つ（いまのストアの決まり〔開いている会話は 1 つ〕のまま）。
- [ ] 返事が進行中の間は、次の発言を受けない（いまと同じ。409）。
- [ ] 返事が終わってから 30 分（定数）、次の発言が無ければ、サーバはその会話の Claude Code のプロセスを止める（会話は閉じない）。時計は返事が終わった時刻から数え、返事が進行中の間（答えを待っている確認がある間を含む）は数えない。
- [ ] プロセスが動いていない開いた会話へ発言を送ると、サーバは Claude Code を起動し直して、その発言を送る（休ませた後・止めた後・サーバを起動し直した後のどれでも同じ）。起動は、会話の始まりの行が出た会話なら `--resume`、出ていない会話なら `--session-id` にする。
- [ ] 「止める」を押すと、サーバはその会話の Claude Code のプロセス（とその子のプロセス）を止める。
- [ ] 「止める」を押すと、サーバは進行中の返事を「止めた」として記録する。
- [ ] 「止める」を押す前に出た分は、止めた後も残す。
- [ ] 「止める」の後の次の発言は `--resume` で続ける。
- [ ] 「新しい会話」を押すと、いまの会話を閉じ、その Claude Code のプロセスを止める。返事が進行中のときは受けない（409。いまと同じ）。
- [ ] 1 回の返事に、ターン数と時間の上限を置かない（ターミナルの Claude Code と同じ。止めるのはオーナーの「止める」）。
- [ ] サーバを止めるとき、動いているすべての Claude Code のプロセスを止める。進行中の返事は「止めた」、答えを待っていた許可の確認と問いは「答えられなかった」として記録する。
- [ ] サーバを起動したとき、進行中のまま残った返事を「止めた」に、答えを待ったまま残った許可の確認と問いを「答えられなかった」にする（いまの起動の片付けに足す。ストアの無いワークスペースは作らずに飛ばす）。

### 返事・道具の使用・途中経過を流して出す

- [ ] 返事の文は、Claude Code が 1 つの発言を出し終えるごとに、ストアの返事の行へ足す（いまと同じ。1 文字ずつでなくてよい）。
- [ ] Claude Code が道具を使い始めたとき、返事の行の道具の一覧へ、道具の名前と対象の 1 行を「実行中」として足す。対象の 1 行は、シェルのコマンドの道具ではコマンドの行、ファイルを読む・書く・直す道具ではファイルのパス、検索の道具では検索の語、スキルの道具ではスキルの名前、サブエージェントの道具では頼んだ作業の説明、それ以外の道具では空にする。
- [ ] 道具の一覧の各行は、Claude Code が付けた道具の使用の識別（`id`）を持つ。道具の結果が届いたとき、同じ識別の 1 行を成否（成功・失敗）に変える。
- [ ] 返事が止まった・失敗した（終わりの行が届かずに終わった）とき、その返事の道具の一覧で `running` のまま残った行を `error` にする。
- [ ] 道具の一覧の対象の 1 行は、長さの上限（200 文字）で切る。道具の入力の全文と結果の中身は、ストアへ写さない。
- [ ] シェルのコマンドだけでなく、すべての道具を一覧に載せる（道具の種類で絞らない）。
- [ ] サブエージェントの中の発言と道具の使用は、一覧に載せない（サブエージェントの道具の 1 行だけを載せる。いまと同じ）。
- [ ] 画面は、いまある変化の知らせ（ストアの変化の SSE）を受けて読み直し、出来た分を出す（新しい SSE の口は作らない）。
- [ ] 欄に、返事の下の道具の一覧を出す。`state` が `running` の行は文言「実行中」を出し、`ok`・`error` の行には出さない。

### 許可の確認と選択肢の問いを、画面のボタンで受ける

- [ ] Claude Code が許可の確認を求めたとき（`control_request` の `can_use_tool`）、サーバはそれを、進行中の返事に結び付いた「確認」としてストアへ記録し、答えを待つ。
- [ ] 確認のうち、道具の名前が AskUserQuestion で、`requires_user_interaction` が真のものは「問い」、ほかは「許可の確認」として記録する（AskUserQuestion 以外で `requires_user_interaction` が真のものも、許可の確認として扱う）。
- [ ] 許可の確認には、道具の名前と、対象の全文を記録する。対象の全文は、シェルのコマンドの道具（Bash）ではコマンドの全文、それ以外の道具では道具の入力を JSON の文字列にしたもの。切らない（道具の一覧の対象の 1 行の 200 文字の切り詰めとは別）。
- [ ] 問いには、問いの文・選択肢（見出しと説明）・複数を選べるかを記録する。
- [ ] 欄は、答えを待っている確認を、その返事の中に出す。
- [ ] 許可の確認には「許可する」と「断る」のボタンを出す。「断る」には、Claude Code へ伝える文を添えられる（任意）。
- [ ] 「許可する」を押すと、サーバはその 1 回だけを許す答えを Claude Code へ返す。設定のファイルへ許可を書き足す答え（以後も許す）は返さない。
- [ ] 「断る」を押すと、サーバは断る答え（添えた文があれば、それも）を Claude Code へ返す。
- [ ] 問いには、選択肢ごとのボタン（複数を選べる問いは、チェックと「送る」）と、選択肢に無い答えを文で書く欄を出す。
- [ ] 問いに答えると、サーバは答えを Claude Code へ返し（`updatedInput.answers`）、返事が続く。
- [ ] 答えた確認は、答え（許可した・断った・問いへの回答）と答えた時刻を記録し、欄に答えの結果を出す（ボタンは出さない）。
- [ ] 答えは、先に Claude Code へ送り、送れたらストアに記録する。送れなかった（プロセスが終わっていた・書き込めなかった）ときは、確認を「答えられなかった」にして、答えを受けない（409）。
- [ ] 答えを待っていない確認（答えた後・答えられなかった）への答えは、受けない（409）。
- [ ] 進行中の返事が止まった・失敗した・Claude Code のプロセスが終わったとき、答えを待っていた確認は「答えられなかった」にする。
- [ ] 答えを待っている確認がある間も、「止める」を押せる。

### 閉じた会話の一覧と、続き

- [ ] 欄に、会話の一覧（閉じた会話を含む。新しい順）を出す。各行は、始めた時刻・最初の発言の先頭・費用の合計・紐づいた課題の題名。
- [ ] 一覧から閉じた会話を選んで「続ける」を押すと、いまの会話を閉じて、その Claude Code のプロセスを止め、選んだ会話を開いた会話にする。次の発言は、その会話の識別で `--resume` して送る。返事が進行中のときは受けない（409）。
- [ ] 判定の順は、無い識別は 404、すでに開いている会話は何もせず成功（返事が進行中でも）、それ以外で返事が進行中なら 409、それ以外でセッションのファイルが見つからない会話なら 409（`transcript_unavailable`）。409 のときは、いまの会話を閉じない。
- [ ] 一覧の各行から、その会話の全文（下の「全文を開く」）を開ける。

### 許可の正本を Claude Code の設定にする（`chat_tools` をやめる）

- [ ] 欄の Claude Code は、利用者の設定（ホームの `~/.claude/settings.json`）とワークスペースの設定（`.claude/settings.json`）を、ターミナルの Claude Code と同じに読む形で起動する（設定の出どころを空にする指定〔`--setting-sources ""`〕・許す道具と禁じる道具の指定・すべて許す指定を付けない）。
- [ ] 設定で許した操作は尋ねずに進み、それ以外は上の許可の確認で画面へ届く（Claude Code の既定の許可の扱いに任せる。flywheel は許可の扱いを指定しない）。
- [ ] 宣言（`.flywheel/agent.json`）から `chat_tools`・`chat_max_turns`・`chat_timeout_sec` を外す。残っている宣言は、無くした項目として読み込みを誤り（`config_invalid`。項目の名前と語 `removed` を出す。いまの無くした項目と同じ扱い）にする。
- [ ] 欄から起動した flywheel のコマンドの一覧の検査（いまの `restricted` のときの検査）をやめる。印があるときの扱いは、いまの `full` のときと同じにする（印の検査・経路 `chat` での記録・不可逆操作の種類の絞り〔宣言 `chat_approvable_operations`〕はかける）。
- [ ] 宣言の `chat_approvable_operations` は残す（既定は反映〔`release`〕だけ。いまと同じ）。
- [ ] 欄の上の、道具の範囲の表示（「すべての道具を許可しています」）を外す。

### `flywheel init` が Claude Code の設定のファイルを作る

- [ ] `flywheel init` は、ワークスペースの `.claude/settings.json` が無いときだけ、下の「init が作る設定」の内容で作る（`.claude/` が無ければ作る）。
- [ ] `.claude/settings.json` があれば、中身によらず触らない（読みもしない）。
- [ ] `flywheel init` の出力（`--json` と文）に、設定のファイルを作ったかを足す。

### 作業フォルダと指示文

- [ ] 欄の Claude Code は、エージェントのワークスペースを作業フォルダにして起動する（いまと同じ）。
- [ ] `flywheel` の名前で、サーバと同じバイナリが動くようにする（いまの、一時のディレクトリにシンボリックリンクを置いて `PATH` の先頭に入れる作りを、返事ごとからプロセスごとに変える。プロセスが終わったら消す）。
- [ ] 欄の指示文（`internal/invoker/prompts/chat.md`）から、道具の範囲（`restricted`・`full`）による振る舞いの分けを外す。
- [ ] 指示文は、対象のリポジトリへ文書を書くときに、`.flywheel/repos/` の下の本体のクローンでブランチを切り替えず、作業ツリーを分けて作ることを求める。
- [ ] 指示文は、課題の作成・承認・回答をすると会話が課題に自動で紐づくので、紐づけのための操作は要らないことを伝える。
- [ ] 発言とともに Claude Code へ渡す入力から、「道具の範囲」の行を外す（いま見ているもの・オーナーの発言は、いまと同じ）。

### 会話を課題に紐づける

- [ ] 欄から起動した flywheel のコマンドが、課題を作る（`create`、または取り込み元を指定して課題を作る `ingest`）・承認・差し戻し・回答（選択肢で答えるもの・計画の作り直しを含む）・取り下げ・予算の増額のどれかを成立させたとき、core は、同じ書き込みの中で、その会話をその課題に紐づける。
- [ ] 紐づけは、会話と課題の組ごとに 1 つ（同じ組の 2 回目からは足さない）。最初に紐づいた時刻と、紐づけた操作の種類を持つ。同じ組の 2 回目からの操作でも、下の「費用」の振り分けは行う。
- [ ] 操作が断られた・失敗したときは、紐づけない。
- [ ] ターミナルの対話のセッションの記録（`--relayed`）は、紐づけない。
- [ ] 欄の Claude Code に渡す印は、会話の識別（`FLYWHEEL_CHAT_SESSION`）だけにする（発言の識別 `FLYWHEEL_CHAT_MESSAGE` と道具の範囲 `FLYWHEEL_CHAT_TOOLS` は外す。プロセスを残すと、環境は起動のときに決まり、発言ごとに変えられないため）。
- [ ] 印の検査は、印の会話が開いていて、その会話の最後のオーナーの発言への返事が進行中であることを確かめる（発言は、印からではなく、core がストアで引く）。
- [ ] 経路 `chat` の記録の「発言」（`relay_quote`）には、その会話の最後のオーナーの発言の文面に、その返事の中で答えた問いの回答（問いの文と答え。答えた順）をつなげたものを入れる。

### 費用（仕様づくり）

- [ ] Claude Code が返事の終わりに返す費用（`total_cost_usd`）は会話の累計として読み、返事の費用は、その会話で前に記録した累計との差にする（前の累計より小さい値が返ったときは、その値をそのまま返事の費用にする）。
- [ ] 会話ごとに、最後に記録した累計を持つ（`--resume` で起動し直しても、差で数える）。
- [ ] 会話が課題に紐づいたとき、その会話の、まだどの課題にも数えていない返事（紐づけを起こした返事と、それ以前の返事）の費用を、その課題の「仕様づくり」の費用として数える。
- [ ] すでに紐づいている会話と課題の組への 2 回目からの操作（例: 欄で `create` した課題を、後の返事で同じ欄から承認する）が成立したときも、その会話の、まだどの課題にも数えていない返事の費用を、その課題の仕様づくりの費用として数える（紐づけの行は足さない）。
- [ ] 振り分けは紐づけの書き込みの中で行い、まだ数える先の決まっていない返事の行（進行中の返事を含む）に、その課題を数える先として書く。すでに数える先のある返事の行は変えない。進行中の返事の費用は、返事を終えるときに確定し、その行の数える先の課題に入る。
- [ ] 終わりの行が届かなかった返事（止めた・失敗した）の費用は 0 とする。その分は次の返事の累計の差に含まれる。
- [ ] 1 つの返事の中で 2 つ以上の課題に紐づいたときは、その返事までの費用を、最初に紐づいた課題に数える。
- [ ] 課題に数えた後の返事は、次に紐づくまで、どの課題にも数えない。
- [ ] 仕様づくりの費用は、実装の枠・レビュー対応の枠・課題の上限・見込みの計算に数えない。
- [ ] 仕様づくりの費用は、サイクルの費用と、サイクルの費用の上限に数えない（いまと同じ）。
- [ ] 課題の詳細（画面と `flywheel show --json`）に、仕様づくりの費用と、紐づいた会話の一覧（始めた時刻・最初の発言の先頭・その課題に数えた費用）を足す。
- [ ] 欄に、いまの会話の費用の合計を出す（いまと同じ）。

### 全文を開く

- [ ] 会話の全文は、Claude Code のセッションのファイルを正本にし、ストアへは写さない。
- [ ] 画面から、会話の全文（オーナーの発言・返事の文・道具の使用〔名前と入力〕・道具の結果）を読み取りだけで開ける。
- [ ] 全文の道具の結果は、1 つにつき 4,000 文字で切り、切った旨を出す。
- [ ] 全文のファイルが見つからない・読めないときは、その旨（Claude Code が古い会話を消したことがありうる）と、発言と返事は欄の記録で読めることを出す。

### うまくいかないとき

- [ ] Claude Code が見つからないときは、発言を送る操作を誤りにし、欄に Claude Code が要る旨を出す（いまと同じ。発言は記録しない）。
- [ ] 返事の途中で Claude Code のプロセスが終わったときは、その返事を「失敗」として記録する（それまでに出た分は残す）。次の発言は `--resume` で続ける。ただし、サーバが自分で止めたプロセス（止める・新しい会話・続ける・サーバの停止）の終わりは「止めた」にし、「失敗」にしない。
- [ ] 進行中の返事が無いときの `POST …/chat/stop` は、いまの口と同じく、何も変えずに成功（204）を返す（動いているプロセスも止めない）。
- [ ] 返事が進行中でないときに Claude Code のプロセスが終わったときは、何も記録しない（次の発言で `--resume` する）。
- [ ] 利用上限に当たったときは、その返事を「利用上限」として記録する（いまと同じ）。
- [ ] `--resume` で会話の続きが見つからないときは、その返事を「会話を続けられなかった」として記録し、会話を閉じる（いまと同じ）。

## 非機能要件

- セキュリティ: 対話の欄の口（発言・止める・新しい会話・確認への答え・会話の一覧・続ける・全文）は、いまの画面の口と同じ守り（`127.0.0.1` だけで待ち受ける・Host と Origin の検査・書き込みは CSRF の値）を通す。
- 機密: 全文はストアへ写さず、読むたびにセッションのファイルから読む。ストアに残すのは、発言と返事の文・道具の 1 行・確認の表示・費用・紐づけだけ。
- 動作環境: macOS と Linux（いまと同じ）。

## 技術的な制約・方針

- 変更対象:
  - `internal/core`: 会話と確認と紐づけの記録（マイグレーション 1 本）と、その公開の API。対話の実行のインターフェース（会話の単位で起動し、発言を送り、確認へ答え、止める形）。印の環境変数（会話の識別だけ）。印の検査と記録の「発言」の作り方。紐づけと費用の振り分け。宣言の 3 項目を無くした項目にする。`Init` が設定のファイルを作る（下の「Claude Code に固有の形は invoker に閉じる」の例外。理由もそこに書く）。課題の詳細の仕様づくりの費用と紐づいた会話。
  - `internal/invoker`: Claude Code の起動（`stream-json` の入出力・許可の確認の受け渡し・`--resume`）、出力の読み取り（発言・道具の使い始めと結果・確認・終わりの行と費用）、全文のファイルの読み取り、指示文。
  - `internal/cli`: 一覧の検査をやめる。印から発言の識別を外す。`init` の出力。`serve` が invoker を組み立てて渡すのは、いまのまま。
  - `internal/server`: 対話の口（下の「画面・API設計」）。プロセスの寿命の管理（休ませる・止める・サーバの停止と起動の片付け）。`internal/invoker` を import しない決まりのまま、core のインターフェースで受け取る。
  - `internal/view`・`web/src`: 型と、欄の部品（道具の一覧・確認のボタン・会話の一覧・全文）。課題の詳細の仕様づくりの費用と紐づいた会話。偽の API（`web/src/mock`）。
- Claude Code に固有の形（引数・`stream-json` の形・`control_request` と `control_response` の形・セッションのファイルの置き場所と形）は `internal/invoker` の中に閉じる。core のインターフェースへは持ち込まない（いまの決まりのまま）。
  - 例外: `flywheel init` が作る `.claude/settings.json`（置き場所と中身）は、core の `Init` に置く。理由は 2 つ。(1) 判断点の呼び出しでも、Claude Code が読む設定の出どころ（`SettingSources`）は core が決めて invoker は引数へ写すだけにしており、Claude Code の設定に関わる決めごとを core に置く前例がある。(2) `init` は core の口（`Init`）で、ワークスペースに作るものは core が決める。invoker は Claude Code を起動する層で、`init` からは呼ばれない。
- **形は実物の出力で固める**: 最初のチケットで、実物の Claude Code の出力（発言・道具の使用・許可の確認・問い・2 回の返事の終わりの行の費用・`--resume` の後の費用）を 1 回取り、その写しを試験のデータ（`internal/invoker/testdata`）に置く。テスト用の実行エンジンは、その写しの形で場面ごとの出力を出す。費用の累計の読み方（同じプロセスの 2 回目の返事・`--resume` の後）は、この写しで確かめてから実装する。止めた後の `--resume` で費用の累計が引き継がれるか（止めた返事の分が次の返事の累計に含まれるか）と、`requires_user_interaction` が真になる確認の範囲（AskUserQuestion のほかにあるか）も、この写しで確かめる。起動の引数（`--input-format stream-json`・`--permission-prompts host`・`--permission-prompt-tool stdio` の併用）も、同じときに実物で確かめる（名前が違えば実物に合わせ、PR の説明に「仕様への指摘」として書く）。
- 確認の答えの記録の形: 許可の確認は `{"decision": "allow" か "deny", "message": 文か null}`、問いは `{"answers": {問いの文: 答えの文}}`（複数を選んだ問いの答えは、選んだ見出しを「, 」でつないだ 1 つの文。Claude Code へ返す形と同じ）。記録の「発言」へつなぐ形は、最後のオーナーの発言の文面の後に、答えた問いごとに空行を挟んで「問い: <問いの文>」「答え: <答えの文>」の 2 行。
- 全文のファイルの置き場所（Claude Code の設定のフォルダの下で、会話の識別を名前に持つファイル）は、invoker が探す。決まりは invoker に閉じ、最初のチケットで実物で確かめる。
- ストアが正。サーバがストアの外に持つのは、動いている Claude Code のプロセスと、その入出力の管、休ませるための時計だけ。返事の進み・道具の一覧・確認は、ストアへ書き、いまある変化の知らせで画面へ届く。
- ストアの版は、いまの版（40）の次（並べて進めているほかの区切りが先に版を使ったら、その次）。書き出しと読み込み（`export`・`import`）に、足した表と列を入れる（ほかの表と同じに、行をそのまま書き出す）。
- 欄の Claude Code は、サイクルの排他を取らない（いまと同じ）。
- 対話の実行のインターフェースは、判断点の呼び出しと同じく core に置き、invoker が実装する（いまの置き場のまま）。

## 画面・API設計

- 試作は作らない（オーナーの決定 2026-11-25）。いまの対話の欄に足す形で、出るものと振る舞いをこの節に書き、見た目は実装の後に実物で見て直す（見た目の作り込みは後の区切り）。
- 欄に出るもの（いまの欄に足す・変える分）:
  - 返事の下の道具の一覧（たためる）。1 行に、道具の名前・対象の 1 行・状態（実行中・成功・失敗）。いまの「実行したコマンド」の一覧を置き換える。
  - 返事の中の確認。許可の確認は、道具の名前・対象の全文（Bash ならコマンドの全文。切らない）・「許可する」「断る」（断る理由の文は任意）。問いは、問いの文・選択肢のボタン（複数を選べる問いはチェックと「送る」）・選択肢に無い答えの文の欄。答えた確認は、答えの結果だけを出す。
  - 会話の一覧（欄の上のボタンで開く）。各行に、始めた時刻・最初の発言の先頭・費用の合計・紐づいた課題の題名・「全文」・（閉じた会話で、セッションのファイルが残っているものだけ）「続ける」。セッションのファイルが無い会話は、「全文」の代わりに「全文はもう無い」と出す。
  - 全文の画面（読み取りだけ）。
  - 外すもの: 道具の範囲の表示。
- 課題の詳細に出るもの: 費用の欄に「仕様づくり」の額（実装の予算に数えない旨を添える）。紐づいた会話の一覧（始めた時刻・最初の発言の先頭・この課題に数えた費用・「全文」）。
- 口（エージェントごと。書き込みは、いまの画面の口と同じ守り。経路の名前は実装で決めてよい。役割はこのとおり）:
  - `GET …/chat`（いまの口に足す・変える）: `tools` を外す。`messages[]` の `activity[]` の要素を `id`（道具の使用の識別）・`tool`・`target`・`state`（`running`・`ok`・`error`）にする（いまの行の `command`・`ok` は、`id` を空、`tool` を `Bash`、`state` を `ok`・`error` として読む）。`messages[]` の要素に `prompts[]`（確認。下の形）を足す。
  - `prompts[]` の要素: `id`・`kind`（`permission`・`question`）・`state`（`pending`・`allowed`・`denied`・`answered`・`expired`）・`tool`・`target`（許可の確認だけ。対象の全文で、切らない。道具の一覧の `activity[]` の `target` の 200 文字の切り詰めとは別）・`questions[]`（問いだけ。`question`・`options[]`〔`label`・`description`〕・`multi_select`）・`answer`（答えの結果。答えていなければ `null`）・`created_at`・`answered_at`。
  - `POST …/chat/prompts/{id}/answer`: 確認への答え。許可の確認は `decision`（`allow`・`deny`）と `message`（断るときの文。任意）。問いは `answers`（問いの文ごとの答えの文）。答えを待っていない確認は 409。ほかのエージェントの確認・無い識別は 404。形の誤り（種類に合わない入力・空の答え）は 400。答えは先に Claude Code へ送り、送れたらストアに記録する。送れなかった（プロセスが終わっていた・書き込めなかった）ときは、確認を `expired`（答えられなかった）にして 409（答えは記録しない）。
  - `GET …/chat/sessions`: 会話の一覧。要素は `id`・`started_at`・`closed_at`・`first_message`（最初の発言の先頭）・`cost_usd`・`challenges[]`（紐づいた課題の `challenge_id`・`title`）・`open`（開いている会話か）・`transcript_available`（セッションのファイルが見つかるか）。
  - `POST …/chat/sessions/{id}/resume`: 閉じた会話を続ける（いまの会話を閉じ、選んだ会話を開く）。判定の順は、無い識別は 404、すでに開いている会話は何もせず成功（返事が進行中でも）、それ以外で返事が進行中なら 409、それ以外で `transcript_available` が偽の会話なら 409（エラーコード `transcript_unavailable`）。409 のときは、いまの会話を閉じない。
  - `GET …/chat/sessions/{id}/transcript`: 全文。`entries[]` の要素は `kind`（`owner`・`assistant`・`tool_use`・`tool_result`）・`text`・`tool`（道具の使用と結果だけ）・`truncated`（結果を切ったか）・`at`。全文のファイルが見つからない・読めないときは 404（エラーコード `transcript_unavailable`）。
  - `POST …/chat/messages`・`POST …/chat/stop`・`POST …/chat/new`: いまの口のまま（形は変えない）。
- 課題の詳細（画面の詳細の口と `flywheel show --json` が共有する形）に足す値: 仕様づくりの費用（`spec_cost_usd`）と、紐づいた会話の一覧（`chat_sessions[]`。要素は `id`・`started_at`・`first_message`・`cost_usd`〔この課題に数えた額〕）。
- `flywheel init --json` に足す値: 設定のファイルを作ったか（`claude_settings_created`）。
- 費用の表示は、いまと同じ `$0.42` の形（小数 2 桁）。
- init が作る設定（`.claude/settings.json`）の内容:

```json
{
  "permissions": {
    "allow": [
      "Bash(flywheel:*)",
      "Bash(gh issue view:*)",
      "Bash(gh issue list:*)",
      "Bash(gh pr view:*)",
      "Bash(gh pr list:*)",
      "Bash(gh pr checks:*)",
      "Bash(gh pr diff:*)"
    ]
  }
}
```

## クリティカル設計決定

### 外部システム連携: Claude Code を会話ごとに起動したまま続ける（区切り S4d-1 の「返事ごとに起動する」を改める）

- **採用案**: 対話の実行のインターフェースを、返事 1 回の形から、会話の単位の形に変える（起動する〔新しい会話か続き〕・発言を送る・確認へ答える・止める。途中の分は、発言・道具の使い始め・道具の結果・確認・返事の終わり〔終わり方と費用の累計〕・プロセスの終わりを、呼び出し元の関数で順に渡す）。実装は `internal/invoker`、置き場は core のまま。
- **プロセスの寿命**:
  - 数: エージェントごとに高々 1 つ（開いている会話が 1 つなので）。エージェントをまたぐ上限は置かない（登録したワークスペースの数で決まる）。
  - 放置: 返事が終わってから 30 分、次の発言も確認も無ければ止める（会話は閉じない）。値は定数で、宣言の項目にしない。
  - 止める: 「止める」はプロセス（とその子）を止める。返事の途中を割り込みで止めてプロセスを残す形は採らない。次の発言は `--resume` で続ける。
  - サーバの停止と起動: 停止のときはすべて止め、起動のときに残った返事と確認を片付ける。サーバが強制終了したときは、Claude Code の標準入力の管が閉じ、Claude Code がそれを見て終わることに頼る（プロセスの識別をストアに残して次の起動で止める仕組みは足さない）。終わることは要人間判定で確かめ、残るときは main へ入れずにオーナーへ上げる（そのときは、プロセスの識別を残して次の起動で止める仕組みを足す案を出す）。
  - 上限: 1 回の返事のターン数・時間の上限は置かない。
- **理由**: オーナーの決定 1（2026-11-24）と決定 8（2026-11-25。放置の 30 分と、値を固定にすること）。長い作業（仕様づくり）は、30 ターン・600 秒の上限と、返事ごとの起動では続かない。止める形をプロセスの停止にするのは、`--resume` での続きを決定 1 の試しで確かめていて、割り込みの形は確かめていないため。放置を止めるのは、動かないプロセスがメモリを持ち続けるのを避けるため（費用は掛からない）。
- **代替案**: (1) 返事ごとに `--resume` で起動する（いまの作り）。許可の確認と問いを答えるまで待てないので採らない。(2) 放置を止めない。メモリを持ち続けるので採らない。(3) 割り込みで返事だけ止め、プロセスを残す。実物で確かめていないので、この区切りでは採らない。(4) 放置の時間を宣言の項目にする。宣言を増やさないため、定数にする。
- **影響範囲**: `internal/core`（インターフェース）・`internal/invoker`・`internal/server`・`CLAUDE.md` のパッケージの表（ストアの外に持つ状態の例外）。

### 承認の真正性・セキュリティ: 許可の確認と問いを、画面のボタンで受ける

- **採用案**: 許可の確認と問いを、ストアに「確認」として記録し、画面のボタンで答える。守りは、いまの画面の口と同じ（`127.0.0.1` だけで待ち受ける・Host と Origin の検査・CSRF）に、次を足す。(1) 答えは、答えを待っている確認の識別へ 1 回だけ受ける（core が書き込みの中で確かめる）。(2) 許可の確認への答えは、その 1 回だけを許す。設定のファイルへ許可を書き足す答え（以後も許す）は返さない。(3) 答えはストアに残り、後から見分けられる。(4) サーバに遠隔の口（区切り S5）を足すときも、対話の欄の口は同じマシンからの接続だけで受ける（設計書 §12.4 の 3 の「同じマシンからの接続に限る」を、ターミナルの代わりのこの欄にも当てる）。
- **受け入れた危険**（決定 8。2026-11-25 に訂正して決め直した）: サーバは要求の送り手を見分けない（設計書 §9）。同じマシンのプロセス（委譲の子を含む）は、画面の HTML から CSRF の値を取って、欄へ文を送り、許可の確認に「許可する」と答えられる。さらに、許可のボタンで任意のコマンドを許せるので、欄の Claude Code は、印を外したシェルでターミナルの対話の記録の形（`--relayed`）で承認を記録でき、欄から承認できる不可逆操作の種類の絞り（宣言 `chat_approvable_operations`）も壁にならない。つまり、欄を通してオーナーの権限で何でも起こせる。これは、設計書 §9 の `full` の宣言のワークスペースで受け入れている危険と同じで、ターミナルの Claude Code で許可を出して使うときと同じ危険である。この区切りから、すべてのワークスペースが負う。守りは、エージェントが手順を守ることに頼る。歯止めは、(a) 許可の確認にコマンドの全文を出し（切らない）、オーナーが何を許すかを見て決められること、(b) 指示文での求め、(c) 承認が記録に残り、経路で後から見分けられること、と、(d) 委譲の子にだけ起動の引数でマージと push を禁じる柵（flywheel#1282。この仕様の範囲外）。送り手を見分ける仕組み（パスキーなど。決定 D18 で外した）は足さない。
- **代替案**: (1) 許可の確認を画面で受けず、尋ねる操作はすべて断る（`--permission-prompts none`）。オーナーの決定 5（ターミナルと同じ動き）に合わないので採らない。(2) 許可のボタンに、操作ごとの本人確認（パスキー）を求める。D18 で、普通の開発の承認に毎回の生体確認は過剰とした判断と同じで、採らない。(3) 「以後も許す」も画面で受ける。設定のファイルを同じマシンのプロセスが書き足せるようになり、危険が残り続けるので、この区切りでは採らない（設定はオーナーが直す）。(4) 委譲の子に別の認証トークン（資格情報）を渡し、承認の口を分ける。同じ OS の利用者なのでキーチェーンを読めて効きが薄く、管理する秘密が増えるので採らない。
- **影響範囲**: 設計書 §9（経路 `chat` の受け入れた危険を書き直す）・§12.4。`internal/server`・`internal/core`。

### 承認の真正性: 印を会話の識別だけにし、記録の「発言」に問いの回答を含める

- **採用案**: 欄の Claude Code の環境の印は、会話の識別（`FLYWHEEL_CHAT_SESSION`）だけにする。印の検査は、印の会話が開いていて、その会話の最後のオーナーの発言への返事が進行中であること。記録の「発言」には、その最後のオーナーの発言の文面に、その返事の中で答えた問いの回答（問いの文と答え。答えた順）をつなげて入れる。
- **理由**: プロセスを残すと、環境は起動のときに決まり、発言ごとの識別を渡せない。いまの検査も「印の発言がその会話の最後のオーナーの発言で、その返事が進行中」を求めているので、最後のオーナーの発言を core が引けば、確かめる中身は同じ。問いの回答（「承認する」を選んだ、など）が承認の根拠になりうるので、記録の発言に含める。
- **代替案**: (1) 発言の識別をファイルに書いて、flywheel のコマンドが読む。印の値を同じマシンのプロセスが書き換えられる点は環境変数と変わらず、仕組みが増えるので採らない。(2) 問いの回答をオーナーの発言の行として記録する。返事の行が分かれ、「最後のオーナーの発言への返事が進行中」の前提が崩れるので採らない。
- **残る危うさ**: いまと同じ（印は環境変数なので、同じマシンのプロセスは自分で付けられる。返事が進行中の間だけ検査が通る）。返事が許可の確認や問いで長く待つ間も、検査は通る。また、プロセスが返事をまたいで残るので、前の返事で裏で始めたコマンドやサブエージェントが、後の返事の進行中に印の検査を通り、後の返事の発言を根拠に承認を記録しうる（検査は「いま進行中の返事があるか」だけを見て、コマンドがどの返事から始まったかは見分けない）。
- **影響範囲**: `internal/core` の印の検査（`resolveChatMark`）と記録の手がかり。`internal/cli` の印の読み取り。記録の表（`approval` の `relay_session`・`relay_quote`）は変えない。

### DB スキーマ: 確認・紐づけ・費用の振り分けの表と列（版はいまの次）

- **採用案**: マイグレーション 1 本で、次を足す。
  - `chat_session` に `engine_cost_total`（最後に記録した費用の累計。USD の 100 万分の 1 の整数。既定 0）。
  - `chat_message` に `charged_challenge_id`（この返事の費用を数えた課題。NULL 可）。`activity` の要素の形を `id`（道具の使用の識別。道具の結果はこれで突き合わせる）・`tool`・`target`・`state` に変える（列は変えない。過去の要素 `command`・`ok` は読み替える）。返事が止まった・失敗したときは、`running` のまま残った要素を `error` に締める。
  - 表 `chat_prompt`（確認）: `id`・`message_id`（返事の行）・`request_id`（Claude Code が付けた識別）・`kind`（`permission`・`question`）・`tool`・`target`・`questions`（JSON。問いだけ）・`state`（`pending`・`allowed`・`denied`・`answered`・`expired`）・`answer`（JSON。答えていなければ NULL）・`created_at`・`answered_at`。
  - 表 `chat_link`（紐づけ）: `id`・`session_id`・`challenge_id`・`action`（紐づけた操作の種類）・`message_id`（紐づけを起こした返事の行）・`created_at`。`(session_id, challenge_id)` に一意の索引。
- **理由**: 読み込み直しても確認が出て答えられること、サーバを起動し直したときに答えを待つ確認を片付けられること、課題の詳細から会話と費用を引けることに、ストアの行が要る。費用の振り分けを返事の行に持たせると、課題の仕様づくりの費用は 1 つの足し算で読め、後から紐づけが増えても振り分け直さない。
- **代替案**: (1) 欄の費用を実行の記録（表 `run`）に、新しい種類の行として入れる。実行の一覧・指標・サイクルの費用の問い合わせへ混ざるので採らない。(2) 紐づけを承認の記録（`relay_session`）から導き、表を足さない。課題を作る操作は承認の記録を残さないので採らない。(3) 確認をサーバのメモリだけに持つ。読み込み直しとサーバの起動し直しの扱いが、ストアが正の決まりから外れるので採らない。
- **影響範囲**: ストアの版が 1 つ進む。`export`・`import` に表 2 つと列 2 つ。いまの開いている会話は高々 1 つの索引は変えない。

### 費用: 累計の差で数え、紐づいた課題へ振り分ける

- **採用案**: 返事の費用は、Claude Code が返す累計と、会話に記録した前の累計の差（小さくなったら、返った値そのもの）。会話が課題に紐づいたとき、その会話の、まだどの課題にも数えていない返事（紐づけを起こした返事まで）を、その課題の仕様づくりの費用にする。1 つの返事で 2 つ以上の課題に紐づいたら、最初の課題に数える。数えた後の返事は、次の紐づけまで、どの課題にも数えない。仕様づくりの費用は、課題の予算（枠・上限・見込み）とサイクルの費用に数えない。
- **理由**: 費用の累計は、`--resume` の後に会話の累計として返る（判断点の呼び出しで実測済み。同じプロセスの 2 回目の返事の値は、最初のチケットの実物の写しで確かめる）。仕様づくりは課題を作る前に行うので、紐づけの前の返事を数えないと仕様づくりの費用が残らない。紐づけの区切りで振り分ければ、同じ会話で別の課題を扱っても、前の課題に後の費用が付かない。予算に数えないのは、オーナーの決定 6（仕様づくりで実装が予算切れにならない）。
- **残る危うさ**: 紐づけを起こした返事を止めた（終わりの行が届かなかった）ときは、その返事の費用は 0 になり、その分は次の返事の累計の差に入る。次の返事は、紐づけの書き込みのときには数える先がまだ決まっていない（すでに数えた後の返事）ので、その課題ではなく、次に紐づく課題へ付きうる。止めた後の `--resume` で累計が引き継がれない場合は、止めた返事の分はどこにも数えられない（最初のチケットで実物で確かめる）。
- **代替案**: (1) 会話の費用の全体を、最初に紐づいた課題に数える。後で別の課題を扱った費用まで前の課題に付くので採らない。(2) 紐づいたすべての課題に等分する。課題を作る前の仕様づくりの費用が、承認しただけの課題にも分かれるので採らない。(3) 紐づけを起こした返事の費用だけを数える。仕様づくりの大半が数えられないので採らない。
- **影響範囲**: `internal/core`（返事を終える API・紐づけ・課題の詳細）・`internal/view`。

### 宣言: `chat_tools`・`chat_max_turns`・`chat_timeout_sec` を無くした項目にする

- **採用案**: 3 項目を宣言から外し、残っている宣言は無くした項目として読み込みを誤りにする（いまの無くした項目の扱い〔`rejectRemovedKeys`。`config_invalid` に項目の名前と語 `removed` を出す〕と同じ）。欄から起動した flywheel のコマンドの一覧の検査もやめる（いまの `full` と同じ扱い）。`chat_approvable_operations` は残す。
- **理由**: オーナーの決定 5（許可の正本は Claude Code の設定のファイル。flywheel は自前の許可の仕組みを持たない）。黙って無視すると、`restricted` のつもりの宣言のまま、絞られていない欄が動く。読み込みを誤りにすれば、オーナーが宣言を直すまで気づける。Tom の宣言には 3 項目が無い（2026-11-25 に確かめた）。
- **代替案**: (1) 黙って無視する。上の理由で採らない。(2) 当面は受けて警告を出す。警告を見る場所が無く、(1) と同じになるので採らない。(3) コマンドの一覧の検査を、設定によらず残す。`bind` などをターミナルと同じに欄から使えず、決定 5 に合わないので採らない。
- **影響範囲**: `internal/core/agent_declaration.go`・`internal/cli`（一覧の検査と、宣言から道具の範囲を読む所）・`internal/invoker`（起動の引数）・設計書 §9・`docs/features/m3-invoker-delegation.md`。**`chat_tools` などを書いたワークスペースは、この区切りの入った版へ上げると、宣言を直すまでサイクルもコマンドも `config_invalid` で止まる**（切り替えの前に宣言を直す）。

### 外部システム連携: 全文を Claude Code のセッションのファイルから読む

- **採用案**: 全文は、読むたびに invoker が Claude Code のセッションのファイルを探して読み、決まった形（発言・返事の文・道具の使用・道具の結果）に直して返す。置き場所の決まりは invoker に閉じる。ファイルが無いときは、読めない旨を返す（ストアの発言と返事は残る）。
- **理由**: オーナーの決定 6（全文はセッションのファイルを正本にし、ストアには写さない）。
- **残る危うさ**: Claude Code は古い会話のファイルを消すことがある（設定 `cleanupPeriodDays`。既定の日数は実物で確かめる）。消えた会話は全文を開けず、`--resume` でも続けられない（「会話を続けられなかった」になる）。そのため、会話の一覧はファイルの有無を返し、無い会話には「続ける」を出さず「全文はもう無い」と出す。保つ日数は利用者が Claude Code の設定で決める（オーナーの決定 2026-11-25）。
- **代替案**: 全文をストアへ写す。決定 6 で採らない。
- **影響範囲**: `internal/core`（インターフェースに全文を読む口）・`internal/invoker`・`internal/server`。

## 機能全体の設計

### 対話の実行のインターフェース（core に置く。名前は実装で決めてよい。役割はこのとおり）

- 起動する: 入力は、会話の識別・新しい会話か続きか・作業フォルダ・環境（印と `PATH`）。戻り値は、動いている会話の手（下の 3 つの操作を持つ）。起動できないときは誤り（Claude Code が見つからないことを見分けられる形）。
- 発言を送る: 入力は、発言・いま見ているもの。
- 確認へ答える: 入力は、確認の識別（Claude Code が付けた識別）と答え（1 回だけ許す・断る〔文つき〕・問いへの答え）。
- 止める: プロセスとその子を止める（プロセスのグループへ合図を送る。いまと同じ）。
- 途中の分（呼び出し元の関数。出力を読む順に 1 つずつ）: 会話の始まり・発言 1 つ・道具の使い始め（道具の名前・対象の 1 行・道具の使用の識別）・道具の結果（識別・成否）・確認（識別・種類・道具の名前・対象の全文・問い）・返事の終わり（終わり方・費用の累計・失敗の要約）・プロセスの終わり。
- 全文を読む: 入力は、会話の識別と作業フォルダ。戻り値は、決まった形の項目の並び。見つからないことを見分けられる形。

### core の公開の API（いまの会話と発言の API に足す・変える。名前は実装で決めてよい）

- 返事の行へ、道具の使い始めを足す／道具の結果で成否を入れる。
- 確認を記録する（進行中の返事の行に結び付ける）／確認へ答える（答えを待っている確認だけ。答えを記録して返す）／答えを待っている確認を「答えられなかった」にする（返事ごと・すべて）。
- 返事を終える: 費用は累計で受け、差を core が数える（会話の累計を更新する）。
- 会話の一覧を読む／閉じた会話を開く（いまの会話を閉じる）。
- 課題を作る・承認などの経路 `chat` の書き込みの中で、紐づけと費用の振り分けを行う（課題を作る操作は、印の検査と同じ印を core へ渡す）。
- 課題の詳細に、仕様づくりの費用と紐づいた会話を足す。

### 実装計画（チケット分解の見通し）

分け方の案（最終の分解は `/create-ticket` で行う）。

1. 土台: マイグレーション（列 2 つ・表 2 つ）、core の確認・紐づけ・費用の振り分け・会話の一覧と続けるの API、印を会話の識別だけにする、宣言の 3 項目を無くした項目にする、対話の実行のインターフェースの形、API の JSON の型（`internal/view`）。実物の Claude Code の出力の写しを取り、試験のデータに置く。
2. 対話の実行（`internal/invoker`）: 起動の引数、`stream-json` の入出力、確認の受け渡し、道具の使い始めと結果の読み取り、費用の累計、止める、全文のファイルの読み取り、テスト用の実行エンジン、指示文の直し。
3. コマンドの側（`internal/cli`・`internal/core`）: 一覧の検査をやめる、印の検査と記録の「発言」、紐づけ、課題の詳細の値、`init` の設定のファイル。
4. サーバ（`internal/server`）: プロセスの寿命（起動・休ませる・止める・停止と起動の片付け）、確認への答え・会話の一覧・続ける・全文の口。
5. 画面（`web/src`）: 道具の一覧・確認のボタン・会話の一覧・全文の画面・課題の詳細の仕様づくりの費用と会話、偽の API、画面の通しの試験。
6. 文書。

順は、1 → 2・3（並行にできる）→ 4 → 5 → 6。

費用の見込み（実装の分）: 2・4・5 が各 15〜25 USD、1・3 が各 12〜20 USD、6 が 6〜10 USD。合計は約 75〜125 USD。

- 返事を 1 文字ずつ流すこと（理由: 発言を 1 つ出し終えるごとと、道具の使い始め・結果ごとに出せば、途中経過は追える。ストアへの書き込みが増えすぎる）
- 返事の途中を割り込みで止めて、プロセスを残すこと（理由: 実物で確かめていない。止めるはプロセスの停止にする）
- 1 つのエージェントで、2 つ以上の会話を同時に開くこと（理由: いまのストアの決まり〔開いている会話は 1 つ〕のまま）
- ターミナルの対話のセッション（`--relayed`）の会話を課題に紐づけること・その費用を数えること（理由: ターミナルのセッションは flywheel が起動しないので、会話と費用を読めない）
- モデル・effort を画面で選ぶこと（理由: ターミナルと同じく、Claude Code の設定のファイルとスラッシュのコマンドに任せる）
- 会話の検索（理由: 一覧と全文で足りる）
- 欄の費用の上限（理由: いまと同じ。オーナーの決定 2026-11-22）
- 画像やファイルを欄に添えること（理由: いまと同じ）
- Tom のワークスペースの切り替え（理由: main に入った後に、オーナーの了承を得て、オーケストレーターが行う）

## 受入基準

S1 の受入基準。core の基準はストアを使う試験で、invoker の基準は実物の写しを使うテスト用の実行エンジンで、サーバの基準は口へ要求を送る試験で、画面の基準は偽の API を使う部品の試験と画面の通しの試験で確かめる。

### 会話と Claude Code のプロセス（invoker・サーバ）

- [ ] 会話の最初の発言で起動する Claude Code の引数に、`-p`・`--input-format stream-json`・`--output-format stream-json`・`--permission-prompts host`・`--permission-prompt-tool stdio` が含まれる。
- [ ] 新しい会話の起動の引数は、flywheel が決めた会話の識別を `--session-id` で渡す。
- [ ] 続きの起動の引数は、会話の識別を `--resume` で渡す。
- [ ] 起動の引数に、`--setting-sources`・`--allowedTools`・`--disallowedTools`・`--permission-mode`・`--max-turns` のどれも含まれない。
- [ ] 同じ会話の 2 通目の発言は、新しいプロセスを起動せず、1 通目と同じプロセスの標準入力へ送られる。
- [ ] 返事が進行中のとき、`POST …/chat/messages` は 409 を返し、発言の行を作らない。
- [ ] 返事が終わってから放置の時間（試験では短くした値）が過ぎると、サーバはその会話のプロセスを止め、会話は開いたまま残る。
- [ ] 放置で止めた後に発言を送ると、`--resume` の引数で起動し直し、その発言が送られる。
- [ ] 返事が進行中の間は、放置の時間が過ぎてもプロセスを止めない。
- [ ] 答えを待っている確認がある間は、放置の時間が過ぎてもプロセスを止めない。
- [ ] `POST …/chat/stop` で、進行中の返事が「止めた」（`stopped`）になる。
- [ ] `POST …/chat/stop` の前に足された返事の文が、stop の後も残る。
- [ ] `POST …/chat/stop` の後、その会話の Claude Code のプロセスとその子のプロセスが終わっている。
- [ ] 会話の始まりの行が出た後の返事を `POST …/chat/stop` で止めると、その後の発言は `--resume` の引数で起動する。
- [ ] 会話の始まりの行が出る前に `POST …/chat/stop` で止めた会話へ発言を送ると、`--resume` ではなく `--session-id` の引数で起動する。
- [ ] 進行中の返事が無いときの `POST …/chat/stop` は 204 を返し、ストアを変えない。
- [ ] 進行中の返事が無いときの `POST …/chat/stop` の後も、その会話のプロセスは動いたままである。
- [ ] 返事の途中でサーバが止めたプロセス（止める・サーバの停止）の終わりで、その返事は `failed` にならない。
- [ ] `POST …/chat/new` で、いまの会話が閉じ、その会話のプロセスが終わる。
- [ ] 返事が進行中のとき、`POST …/chat/new` は 409 を返し、会話を閉じない。
- [ ] 返事が進行中のとき、`POST …/chat/new` は 409 を返し、プロセスを止めない。
- [ ] ストアの無いワークスペースを登録したサーバの起動で、そのワークスペースにストアが作られず、起動が成功する。
- [ ] 返事が 600 秒を超えて進行中でも、サーバは返事を打ち切らない（時計を差し替える試験）。
- [ ] 同じエージェントで、動いているプロセスがある間に 2 つ目のプロセスを起動しない。
- [ ] サーバを止めると、動いていたすべての会話のプロセスが終わり、進行中の返事は `stopped` になる。
- [ ] サーバを止めると、答えを待っていた確認は `expired` になる。
- [ ] サーバの起動のとき、ストアに残った進行中の返事は `stopped` になる。
- [ ] サーバの起動のとき、ストアに残った答えを待つ確認は `expired` になる。
- [ ] 会話の始まりの行が出た、プロセスが動いていない開いた会話（サーバを起動し直した後）へ発言を送ると、`--resume` の引数で起動する。

### 返事・道具の使用・途中経過（invoker・core・画面）

- [ ] 実物の写しの出力を読むと、発言 1 つごとに、返事の行の本文へその発言が足される。
- [ ] 道具の使用の行を読むと、返事の行の道具の一覧へ、道具の名前と対象の 1 行が `running` で足される。
- [ ] 道具の結果が成功の行を読むと、対応する一覧の要素が `ok` になる。
- [ ] 道具の結果が失敗の行を読むと、対応する一覧の要素が `error` になる。
- [ ] 道具の一覧の要素は、道具の使用の識別（`id`）を持ち、道具の結果は同じ識別の要素だけを変える（2 つの道具が同時に `running` のとき、後に届いた結果が先の要素を変えない）。
- [ ] 返事が `stopped` で終わると、その返事の道具の一覧で `running` のまま残った要素が `error` になる。
- [ ] 返事が `failed` で終わると、その返事の道具の一覧で `running` のまま残った要素が `error` になる。
- [ ] シェル以外の道具（ファイルの読み取り・スキル）の使用も、道具の一覧に足される。
- [ ] 200 文字を超える対象の 1 行は、200 文字で切って記録される。
- [ ] サブエージェントの中の発言と道具の使用（親の道具の使用の識別を持つ行）は、返事の行に足されない。
- [ ] 過去の形の道具の一覧の要素（`command`・`ok`）は、`GET …/chat` で `tool` が `Bash`、`state` が `ok` か `error` として返る。
- [ ] 欄は、`state` が `running` の道具の行に文言「実行中」を出し、`ok`・`error` の行には出さない。
- [ ] 道具の結果の中身が、返事の行（本文・道具の一覧）に入らない。

### 許可の確認と問い（invoker・core・サーバ・画面）

- [ ] 実物の写しの許可の確認の行（`can_use_tool`）を読むと、進行中の返事に結び付いた `permission` の確認が `pending` で記録され、道具の名前と対象の全文が入る。
- [ ] 実物の写しの問いの行（道具の名前が AskUserQuestion で `requires_user_interaction` が真）を読むと、`question` の確認が `pending` で記録され、問いの文・選択肢・複数を選べるかが入る。
- [ ] 4,000 文字を超えるコマンドの Bash の許可の確認は、`GET …/chat` の `prompts[]` の `target` にコマンドの全文が切られずに返る。
- [ ] 欄は、許可の確認に、`target` の全文を切らずに出す。
- [ ] 道具の名前が AskUserQuestion でなく `requires_user_interaction` が真の確認の行を読むと、`permission` の確認として記録される。
- [ ] `GET …/chat` は、返事の `prompts[]` に答えを待っている確認を返す。
- [ ] 許可の確認に `decision: allow` で答えると、確認が `allowed` になり、Claude Code へ、その 1 回だけを許す答え（許可の書き足しを含まない）が返る。
- [ ] 許可の確認に `decision: deny` と `message` で答えると、確認が `denied` になり、Claude Code へ、断る答えと添えた文が返る。
- [ ] 問いに `answers` で答えると、確認が `answered` になり、Claude Code へ `updatedInput.answers` に答えを入れた答えが返る。
- [ ] 答えを待っていない確認への答えは 409 で、確認の記録を変えない。
- [ ] ほかのエージェントの確認・無い識別への答えは 404。
- [ ] 許可の確認への `answers` だけの答え・問いへの `decision` だけの答え・空の答えは 400 で、確認の記録を変えない。
- [ ] Claude Code のプロセスが終わった後の、答えを待っていた確認への答えは 409 で、確認は `expired` になり、答えは記録されない。
- [ ] 答えを Claude Code へ送るのに失敗した（テスト用の実行エンジンが送るときに誤りを返す）とき、答えは 409 で、確認は `expired` になり、答えは記録されない。
- [ ] 返事が `stopped`・`failed` で終わると、その返事の答えを待っていた確認は `expired` になる。
- [ ] 欄は、`pending` の許可の確認に「許可する」と「断る」のボタンを出す。
- [ ] 欄は、`pending` の問いに選択肢ごとのボタンと、選択肢に無い答えの文の欄を出す。
- [ ] 欄は、複数を選べる問いに、選択肢ごとのチェックと「送る」を出す。
- [ ] 欄は、答えた確認にボタンを出さず、答えの結果を出す。
- [ ] 欄の「断る」に、Claude Code へ伝える文を添える欄が出る。
- [ ] 欄は、答えを待っている確認がある間も「止める」を押せる。
- [ ] 欄で「許可する」を押すと、`POST …/chat/prompts/{id}/answer` へ `decision: allow` が送られる（画面の通しの試験）。

### 閉じた会話の一覧と続き（core・サーバ・画面）

- [ ] `GET …/chat/sessions` は、閉じた会話を含む会話を新しい順に返し、各要素に最初の発言の先頭・費用の合計・紐づいた課題が入る。
- [ ] `POST …/chat/sessions/{id}/resume` で、いまの会話が閉じ、選んだ会話が開いた会話になる。
- [ ] 続けた会話へ発言を送ると、その会話の識別を `--resume` で渡して起動する。
- [ ] 返事が進行中のときの `POST …/chat/sessions/{id}/resume` は 409 で、どの会話も変えない。
- [ ] 無い識別への `POST …/chat/sessions/{id}/resume` は 404。
- [ ] `transcript_available` が偽の閉じた会話への `POST …/chat/sessions/{id}/resume` は 409（`transcript_unavailable`）で、いまの会話を閉じない。
- [ ] すでに開いている会話への `POST …/chat/sessions/{id}/resume` は、返事が進行中でも成功を返し、会話と返事の行を変えない。
- [ ] 閉じた会話を続けると、それまで開いていた会話の Claude Code のプロセスが終わる。
- [ ] 欄の会話の一覧で、閉じた会話の行に「続ける」が出て、開いている会話の行には出ない。
- [ ] セッションのファイルが無い閉じた会話は、`GET …/chat/sessions` の要素の `transcript_available` が `false` になる。
- [ ] 欄の会話の一覧で、`transcript_available` が `false` の会話の行には「続ける」と「全文」が出ず、「全文はもう無い」が出る。
- [ ] 欄の会話の一覧で、`transcript_available` が `true` の会話の行に「全文」が出て、押すと全文の画面が開く。

### 許可の正本と宣言（core・cli）

- [ ] `chat_tools` を含む宣言の読み込みは `config_invalid` になり、文に項目の名前と `removed` が出る。
- [ ] `chat_max_turns` を含む宣言の読み込みは `config_invalid` になり、文に項目の名前と `removed` が出る。
- [ ] `chat_timeout_sec` を含む宣言の読み込みは `config_invalid` になり、文に項目の名前と `removed` が出る。
- [ ] `chat_approvable_operations` を含む宣言は、いまと同じに読める。
- [ ] 印がある環境で、いまの一覧に無かったコマンド（`bind`）が、一覧の検査で断られない。
- [ ] 印がある環境の記録するコマンド（`approve`）は、いまと同じに印の検査を通る。
- [ ] 印がある環境の、宣言に無い種類の不可逆操作の承認は、いまと同じに断られる。
- [ ] `GET …/chat` の応答に `tools` が無い。
- [ ] 欄に、道具の範囲の表示が出ない。

### `flywheel init` の設定のファイル（core・cli）

- [ ] `.claude/settings.json` の無いワークスペースで `flywheel init` を実行すると、「init が作る設定」と同じ内容の `.claude/settings.json` ができる。
- [ ] `.claude/` の無いワークスペースでも、`.claude/` を作って設定のファイルを作る。
- [ ] `.claude/settings.json` があるワークスペースで `flywheel init` を実行しても、ファイルの中身と更新時刻が変わらない。
- [ ] 中身が JSON でない `.claude/settings.json` があっても、`flywheel init` は誤りにならず、ファイルを変えない。
- [ ] `flywheel init --json` は、設定のファイルを作ったときに `claude_settings_created` が真、作らなかったときに偽を返す。
- [ ] `flywheel init`（`--json` 無し）の文に、設定のファイルを作ったかが出る。

### 作業フォルダと指示文（invoker・サーバ）

- [ ] 欄の Claude Code の作業フォルダは、そのエージェントのワークスペースである。
- [ ] 欄の Claude Code の環境の `PATH` の先頭のディレクトリに、サーバの実行ファイルを指す `flywheel` がある。
- [ ] 欄の Claude Code のプロセスが終わると、`PATH` の先頭に置いた一時のディレクトリが消える。
- [ ] 欄の Claude Code の環境に `FLYWHEEL_CHAT_SESSION` があり、`FLYWHEEL_CHAT_MESSAGE` と `FLYWHEEL_CHAT_TOOLS` は無い。
- [ ] 欄の Claude Code の環境に、委譲の子の印（`FLYWHEEL_DELEGATED_RUN`）は無い（親の環境にあっても渡さない。いまと同じ）。
- [ ] 発言とともに渡す入力に、「道具の範囲」の行が無い。
- [ ] 指示文に、`restricted`・`full` の語が無い。
- [ ] 指示文は、対象のリポジトリへ文書を書くときに本体のクローンでブランチを切り替えず、作業ツリーを分けることを求める文を持つ。
- [ ] 指示文は、課題の作成・承認・回答で会話が課題に自動で紐づくことを伝える文を持つ。
- [ ] 指示文は、指示文の分量の上限の検査と語の検査を通る。

### 印の検査と記録の「発言」（core・cli）

- [ ] 印の会話の最後のオーナーの発言への返事が進行中のとき、印のある `approve` は成立し、記録の「会話の識別」に印の会話の識別が入る。
- [ ] 印の会話の最後のオーナーの発言への返事が進行中でないとき、印のある `approve` は断られ、何も書かない。
- [ ] 印の会話が閉じているとき、印のある `approve` は断られ、何も書かない。
- [ ] 返事の中で問いに答えていないとき、記録の「発言」は最後のオーナーの発言の文面と同じになる。
- [ ] 返事の中で問いに 2 つ答えたとき、記録の「発言」は最後のオーナーの発言の文面に、2 つの問いの文と答えを答えた順につなげたものになる。

### 会話を課題に紐づける（core）

- [ ] 印のある `create` が成立すると、その会話と作った課題の紐づけが、操作の種類 `create` で 1 つできる。
- [ ] 印のある `approve` が成立すると、その会話とその課題の紐づけができる。
- [ ] 印のある `answer` が成立すると、その会話とその課題の紐づけができる。
- [ ] 印のある `reject` が成立すると、その会話とその課題の紐づけができる。
- [ ] 印のある `withdraw` が成立すると、その会話とその課題の紐づけができる。
- [ ] 印のある `budget` が成立すると、その会話とその課題の紐づけができる。
- [ ] 印のある `ingest`（取り込み元を指定した形）が成立すると、その会話と作った課題の紐づけが、操作の種類 `ingest` で 1 つできる。
- [ ] 同じ会話から同じ課題へ 2 回目の操作が成立しても、紐づけは 1 つのままで、最初の時刻と操作の種類が残る。
- [ ] 断られた操作（印の検査に通らない・宣言に無い種類の不可逆操作の承認）では、紐づけはできない。
- [ ] 印の無い `--relayed` の `approve` では、紐づけはできない。

### 費用（invoker・core）

- [ ] 同じ会話の 2 回の返事で累計 0.10・0.25 が返ると、返事の費用は 0.10 と 0.15 になる。
- [ ] `--resume` で起動し直した後の返事で累計 0.40 が返ると（前の累計 0.25）、返事の費用は 0.15 になる。
- [ ] 前の累計より小さい累計（前 0.25・今回 0.05）が返ると、返事の費用は 0.05 になり、会話の累計は 0.05 になる。
- [ ] 累計 0.10 の返事の後、終わりの行が届かずに止めた返事の費用は 0 になる。
- [ ] その次の返事で累計 0.30 が返ると、その返事の費用は 0.20 になる。
- [ ] 実物の写しの、同じプロセスの 2 回目の返事の終わりの行の費用が、上の累計の読み方で数えられる（写しを使う試験）。
- [ ] 会話の 3 回の返事の後、3 回目の返事の中で課題が作られて紐づくと、3 回の返事の費用の合計がその課題の仕様づくりの費用になる。
- [ ] 紐づいた後の返事（4 回目）の費用は、どの課題の仕様づくりの費用にも入らない。
- [ ] 4 回目・5 回目の返事の後、5 回目の返事で別の課題に紐づくと、4 回目と 5 回目の費用がその別の課題の仕様づくりの費用になり、前の課題の仕様づくりの費用は変わらない。
- [ ] 1 つの返事の中で 2 つの課題に紐づくと、その返事までのまだ数えていない費用は、最初に紐づいた課題だけに入る。
- [ ] 紐づけを起こした返事が、紐づけの後に費用を記録して終わっても、その費用はその課題の仕様づくりの費用に入る。
- [ ] 1 回目の返事の `create` で課題に紐づいた後、2 回目・3 回目の返事の後に 3 回目の返事で同じ課題を `approve` すると、2 回目と 3 回目の費用もその課題の仕様づくりの費用に入り、紐づけは 1 つのままである。
- [ ] 仕様づくりの費用がある課題の実装の枠の残りは、仕様づくりの費用が無いときと同じ値になる。
- [ ] 仕様づくりの費用がある課題のレビュー対応の枠の残りは、仕様づくりの費用が無いときと同じ値になる。
- [ ] 仕様づくりの費用がある課題の上限は、仕様づくりの費用が無いときと同じ値になる。
- [ ] 仕様づくりの費用がある課題の見込みは、仕様づくりの費用が無いときと同じ値になる。

- [ ] `flywheel show --json` の課題に、仕様づくりの費用（`spec_cost_usd`）と、紐づいた会話の一覧（`chat_sessions[]`）が入る。

### 全文（invoker・サーバ・画面）

- [ ] 試験のデータのセッションのファイルを読むと、`GET …/chat/sessions/{id}/transcript` は、オーナーの発言・返事の文・道具の使用・道具の結果を、ファイルの順に返す。
- [ ] 4,000 文字を超える道具の結果は、4,000 文字で切られ、`truncated` が真になる。
- [ ] セッションのファイルが無い会話の `GET …/chat/sessions/{id}/transcript` は 404（`transcript_unavailable`）。
- [ ] 全文の画面は、全文が読めないとき、その旨と、発言と返事は欄の記録で読めることを出す。
- [ ] 全文を読んでも、ストアは変わらない。

### うまくいかないとき（invoker・サーバ）

- [ ] Claude Code が見つからないときの `POST …/chat/messages` は 503（`engine_unavailable`）で、発言の行を作らない。
- [ ] 返事の途中でプロセスが 0 でない終了で終わると、その返事は `failed` になり、それまでに足された文が残る。
- [ ] 会話の始まりの行が出た後に `failed` になった会話の次の発言は、`--resume` の引数で起動する。
- [ ] 会話の始まりの行が出る前に `failed` になった会話の次の発言は、`--session-id` の引数で起動する。
- [ ] 返事が進行中でないときにプロセスが終わっても、ストアの発言の行は変わらない。
- [ ] 利用上限の終わりの行を読むと、その返事は `rate_limited` になる。
- [ ] 続きの会話が見つからない出力を読むと、その返事は `session_lost` になり、会話が閉じる。
- [ ] 新しい返事は、終わり方 `limit` にならない。

### 守り（サーバ）

- [ ] `POST …/chat/prompts/{id}/answer` は、CSRF の値が無い・誤りの要求を断り、ストアを変えない。
- [ ] `POST …/chat/sessions/{id}/resume` は、CSRF の値が無い・誤りの要求を断り、ストアを変えない。
- [ ] `POST …/chat/prompts/{id}/answer` は、Host か Origin が同じマシンのものでない要求を断る。
- [ ] `GET …/chat/sessions` は、Host か Origin が同じマシンのものでない要求を断る。
- [ ] `POST …/chat/sessions/{id}/resume` は、Host か Origin が同じマシンのものでない要求を断る。
- [ ] `GET …/chat/sessions/{id}/transcript` は、Host か Origin が同じマシンのものでない要求を断る。
