## 拾い方（網羅性）

- SKILL.md の見出し（`### 0.`〜`### 6.`・`## 出力`・`## 注意`）ごとに全文を通読し、
  「落とし穴」「注意」「〜しない」「〜してはならない」「事故」「症状」
  「実績」「fail-closed」等の語を含む一文・段落を候補として拾った。
- 拾った候補は 1 知見 1 行に要約し、下の表へ入れた。**合計 68 件**。
  内訳: 手順0（観測・取り込み）14 件・手順1（整理）6 件・手順2（計画）10 件・
  手順3（実行）26 件・手順4（検証）2 件・手順5（学習）1 件・手順6（報告・
  コミット）6 件・`## 注意`・`## 出力` 3 件。
- 取りこぼしを避けるため、**迷ったら拾う側に倒した**（明らかに flywheel の
  設計と無関係な定型文〔スキルの説明文・入力引数の説明等〕は除外した）。
- 逐語的に同じ趣旨の知見が複数箇所に現れる場合（例: 「fail-closed」の適用が
  複数の検査対象に繰り返される）は、対象ごとに別の行として残した（同じ規律が
  複数の検査に掛かっていること自体が仕分けの材料になるため、1行へ圧縮しない）。

## 仕分けの基準

| 仕分け | 基準 | 判定の目安 |
|---|---|---|
| **コードの分岐** | 決定的に判定できる規則（入力から出力が一意に決まり、意味判断を要さない） | 「〇〇なら△△」で書け、例外の余地が無い |
| **指示文（該当判断点）** | 意味判断を要する注意で、判断点・委譲の子に伝える必要があるもの。分量の上限（§指示文の歯止め）の範囲でだけ持てる | 子・判断点の Claude が「知らないと誤りうる」注意 |
| **記憶（Markdown）** | 運用の経験則・このエージェント（Tom）や特定 repo・接続ツール固有の事情。flywheel 本体のコードにも指示文にも属さない | 環境依存・バージョン依存・「2026-07時点の実績」等の時限性がある知見 |
| **対象外** | M3 の範囲外（§やらないこと・現行から引き継ぐ振る舞いで「持ち込まない」と明記）、または flywheel のアーキテクチャ（SQLite のトランザクション・ストア設計）が構造的に同じ問題を解消しており、同種の規律を再実装する必要が無いもの | 該当する flywheel の決定事項・受入基準を併記できる |

## この仕分けから見える傾向

- **「対象外」の多く**は、flywheel が SQLite の ACID トランザクション・`run`/`cycle`/`lock` テーブルという構造を持つことで、`claude-flywheel` が Markdown ファイル（台帳・journal・runs.jsonl）の同期・アトミック性・検算のために編み出した規律（一時ファイル→`mv`・検算スクリプト・未終了イベントの LIFO 対応付け）を**丸ごと不要にしている**。これは M3 の設計判断（§クリティカル設計決定1・§アーキテクチャ決定）が意図した効果そのものであり、想定通りの結果と言える。
- **「記憶（Markdown）」に落ちたもの**の多くは、flywheel を呼び出す側（エージェント運用のワークスペース直下。本リポジトリ外）の `CLAUDE.md` に**既に反映済み**（自走委譲の起動・完了報告の様式・1サイクル1セッション等）。反映漏れが見つかったのは「`gh pr edit` の draft 化副作用」の1件で、`agent-memory` への追加記録を推奨する。
- **「指示文（J3固定の節）」に落ちたもの**は「完了報告の様式」「禁止する操作と代替手段」の2節に集中しており、これは §J3 が固定の節としてこの2つを明示的に列挙していることと整合する。
- **「対象外（将来課題）」**（依存関係の解決）は M1 S2 の `challenge_dependency` 実装を待つ。当該チケットの着手時に本表の #22・#31 を再度参照することを推奨する。
